# AGENTS.md

Guidance for AI coding agents working in this repository. Humans: see README.md and CONTRIBUTING.md.

## What this is

An unofficial reference manual ("Detailed Guide") for the Plasticity 3D CAD modeller, reference version
**26.2.0**. Markdown chapters → pandoc (Lua filter + Typst template) → Typst → PDF. It is a documentation
project: the product is the PDF, and **accuracy matters more than anything else**.

## Layout

```
book/chapters/     the manual's text, one file per chapter (NN-name.md; long chapters split NNa/NNb)
book/figures/      SVG diagrams, cNN-name.svg (NN = chapter that uses it)
book/metadata.yaml cover, header/footer, PDF title
theme/             design: template.typ (pandoc), style.typ, components.typ, palette.typ,
                   versions.json (version-tag colours), filter/*.lua (Markdown → Typst calls)
tools/             build.py, check.py (linter), index.py (tool index), common.py (shared paths)
docs/              writing-guide.md, diagram-style.md, build-system.md, review/ (plan, corrections, unresolved)
```

Read before editing: `docs/writing-guide.md` for anything in `book/`, `docs/build-system.md` for `theme/` or `tools/`,
`docs/diagram-style.md` for figures.

## Commands

```bash
make check    # lint chapters (fast; run after every content edit)
make          # index + check + build → build/Plasticity_Manual_<timestamp>.pdf
make typ      # stop at build/manual.typ (Typst errors refer to its line numbers)
make clean
```

Requires pandoc ≥ 3.1, typst ≥ 0.12, Python 3 (stdlib only), DejaVu fonts. `make watch` runs forever: do not use it.
To render one chapter alone, use the preview command in `docs/writing-guide.md` (do not run parallel full builds).

## Content rules (non-negotiable)

- **Never invent** behaviour, defaults, value ranges, key bindings, measurements or introduction dates.
  Add only what the sources state: https://doc.plasticity.xyz and its source
  https://github.com/KioArts/plasticity-document-revisions (raw MDX:
  `https://raw.githubusercontent.com/KioArts/plasticity-document-revisions/main/pages/<path>.en.mdx`).
  Web-fetch tools often paraphrase; use the raw MDX when exact wording matters.
- **Paraphrase.** Never copy passages, screenshots or icons from the official docs.
- **Nothing has been tested in the application.** Never add `tested=` / `{.tested}` or describe the manual as
  verified unless the user gives you a real test result from a named build.
- When sources are silent or conflict: say so in the card (`Unresolved:` section or `[UNRESOLVED]{.unresolved}`)
  and add the item, with the application test that would settle it, to `docs/review/unresolved.md`.
- Every correction to an existing fact goes in `docs/review/corrections.md` with its source.
- Version labels: `version="x.y"` / `[x.y]{.ver}` only when release notes announce it; otherwise
  `documented="x.y"` / `[x.y]{.doc}`. Never guess. A new Plasticity version needs a colour in `theme/versions.json`.
- Do not rename a card's `name="…"` (the tool index and `[Name]{.cmd}` links depend on it) and do not change
  `#`/`##` headings (numbering and cross-references depend on them).
- The tool index in `book/chapters/11-quick-reference-shortcut-card.md` between `<!-- index:start -->` and
  `<!-- index:end -->` is generated by `tools/index.py`: never edit it by hand.
- UK English, second person, short sentences, dates DD/MM/YYYY.

## Changing tooling or theme without changing content

The PDF layout is tuned to match a previous edition; treat any visual change as a content change. For refactors,
prove the output is unchanged:

1. Before: `make`, keep a copy of `build/manual.typ` and the PDF.
2. After: `make` again; the chapter part of `build/manual.typ` must be byte-identical.
3. Render both PDFs (`pdftoppm -r 60 -png`) and compare page images; only the cover's "Built …" timestamp may differ.

## Gotchas

- `theme/template.typ` is a **pandoc template**: never write a dollar sign in it, even in comments
  (pandoc treats `$name$` as a variable; `$body$` in a comment pastes the whole book there).
- Image paths in chapters are root-relative (`book/figures/…`); the filter prefixes `/` for Typst's `--root .`.
- `tools/` scripts import `common.py`; run them as `python3 tools/<script>.py` from the repository root.
- Long cards may break across pages; the rules live in `theme/filter/cards.lua` (weights, head/tail grouping).

## Git and GitHub

- Remote: `git@github.com:leoperria/plasticity-manual.git` (public). `main` is protected by a ruleset:
  PR with code-owner (`@leoperria`) approval, passing `build` check, no force-push or deletion.
  The owner can bypass it; agents should still work on a branch and push or merge only when asked.
- Commit only when asked. Record user-visible changes under `[Unreleased]` in `CHANGELOG.md`.
- CI (`.github/workflows/build.yml`) runs `python3 tools/build.py` and uploads the PDF; keep that entry point working.
- Never commit `memo.md` (private notes, git-ignored) or `.claude/settings.local.json`.
- Releases: tag `vX.Y`, attach a PDF built from the tagged commit with a clean working tree.
